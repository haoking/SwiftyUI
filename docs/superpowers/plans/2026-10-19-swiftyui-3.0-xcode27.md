## Review Focus

1. **最低系统版本上的运行时**:`Mutex`/`Atomic` 在 iOS 18.0 运行时可用,但本机默认测试机是 iOS 27。→ Task 9 在 iOS 18.6 模拟器上再跑一遍全量单元测试。
2. **极端宽高比的图片取色**:细长图片下采样后 H 可达数千行,基数排序的缓冲区随之变大。→ Task 5 的对拍样本含 20×400(H = 5000)。
3. **运行时调低容量但没有新的 `add`**:淘汰只在 `add` 时发生,调低 `memoryCapacity` 本身不淘汰。→ Task 4 的随机对拍序列包含改容量操作。
4. **空字符串与 nil 文本、布局之后再改容器属性**:`SwiftyLabel("")` 与 `SwiftyLabel(nil)` 的尺寸不同;改 `numberOfLines` 之后缓存的布局必须失效。→ Task 6 的对拍覆盖这两条。
5. **非 ASCII 的十六进制串**:全角数字 `Character.isHexDigit` 为 true,带空白、组合字符的串。→ Task 7 的 hex 测试覆盖。

### Task 5: ImageCachePool 的 O(1) LRU

**Files:**

- Modify: `Sources/ImageCacheable.swift`(删 `CachedImage`,加 `ImageLRU`)、`Sources/SwiftyImage.swift`(`ImageCachePool` 改用 `ImageLRU`)
- Test: `Tests/SwiftyUITests/ImageCachePoolTests.swift`

**Interfaces:**

- Produces(全部 internal):
  - `struct ImageLRU`:`private(set) var memoryUsage: UInt64`;`var isEmpty: Bool`;`mutating func insert(_ image: UIImage, for identifier: String)`(已存在则替换并成为最新);`mutating func image(for identifier: String) -> UIImage?`(命中即成为最新);`mutating func remove(_ identifier: String) -> Bool`;`mutating func removeAll()`;`mutating func purge(toFit capacity: UInt64, preferred: UInt64)`;`func identifiersOldestFirst() -> [String]`;`static func cost(of image: UIImage) -> UInt64`(沿用 `宽 × scale × 4 × 高 × scale`)。
  - `ImageCachePool.debugIdentifiersOldestFirst() -> [String]`(只读、不改变新旧顺序,供对拍)。
- 存储:节点放在连续数组里,`older`/`newer` 是下标,空位用空闲表复用;节点释放时清掉 `UIImage` 引用。
- 淘汰规则(逐字保留 2.1.0):`usage > capacity` 时,`toPurge = usage ≥ preferred ? usage − preferred : 0`;从最旧开始删,**每删一个**累加字节,`累加 ≥ toPurge` 即停(因此至少删一个;最新的那个必要时也会被删)。
