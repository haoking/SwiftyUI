# SwiftyUI 2.0.0 现代化改造实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 修复 SwiftyUI 全部 19 个已定位 bug,并将其升级到 iOS 15 基线与 Swift 6 语言模式,建立单元测试与 CI,发布 2.0.0。

**Architecture:** 分六个阶段推进,每阶段结束时代码均可编译、测试均通过。先做零逻辑变更的地基工作(仓库清理、构建配置、测试脚手架),再为现有行为写下基线测试,然后逐条修 bug(先测后改),接着做架构调整(把 associated object 存储下沉为真实存储属性),最后切换 Swift 6 语言模式并完成交付。基线测试必须早于任何逻辑改动,否则无法判断重构是否改变了行为。

**Tech Stack:** Swift 6.0 / Xcode 26.6 / iOS 15.0+ / XCTest / Swift Package Manager / CocoaPods / GitHub Actions

**设计文档:** `docs/superpowers/specs/2026-07-26-swiftyui-modernization-design.md`(本计划中的 B1–B18 编号与该文档 §4.1–4.3 一一对应;B19 为编写本计划时新发现,已回填至该文档 §4.4)

## Global Constraints

- 最低部署目标:**iOS 15.0**。不写任何 `#available` 版本分支。
- Swift 工具链:`swift-tools-version: 6.0`。语言模式分阶段推进:Phase A–E 前期用 `.v5`,Task 17 起切换到 `.v6`。
- 版本号:**2.0.0**,需同步 `SwiftyUI.podspec`、`CHANGELOG.md` 与 git tag。
- **不引入任何第三方依赖。**
- 不重写核心渲染策略:`layer.contents` 承载图片、TextKit 自绘文字的架构保持不变。
- 不新增功能特性(README "To Do List" 中的 CameraKit / OpenGL / Metal / OpenCV / Vision 均不在范围内)。
- 所有 UI 类型最终必须是 `@MainActor` 隔离的;从后台线程设置 UI 属性将成为编译错误,这是本次已接受的破坏性变更。
- **不能使用 `swift build` 或 `swift test`**:本包仅依赖 UIKit,在 macOS 宿主上会因 `cannot load underlying module for 'UIKit'` 失败(已实测)。一律使用 `Scripts/build.sh` 与 `Scripts/test.sh`(Task 2 创建)。
- 工作分支:`feature/2.0-modernization`。每个 Task 至少提交一次;Task 内部有多个逻辑边界时(如 Task 16 的"纯移动"与"改逻辑")分开提交,以便分别审查。
- 破坏性 API 变更须同步记入 `CHANGELOG.md`(Task 21 统一整理,但每个 Task 改动时先在提交信息中写清)。

- [ ] **Step 3: 创建 Scripts/build.sh**

```bash
#!/usr/bin/env bash
# 构建 SwiftyUI 库。
# 不能用 `swift build`:本包仅依赖 UIKit,在 macOS 宿主上会失败。
set -euo pipefail
cd "$(dirname "$0")/.."

LOG=".build/build.log"
mkdir -p .build

# 完整输出落盘,再筛出有用的行。
# 不要用 `xcodebuild | grep ... || true` 再取 PIPESTATUS:`|| true` 是一条
# 简单命令,会把 PIPESTATUS 重置为 (0),真实失败会被吞掉。
set +e
xcodebuild build \
  -workspace .swiftpm/xcode/package.xcworkspace \
  -scheme SwiftyUI \
  -destination 'generic/platform=iOS Simulator' \
  -derivedDataPath .build/xcode \
  "$@" > "$LOG" 2>&1
status=$?
set -e

grep -E '^(/.*(error|warning):|\*\* BUILD)' "$LOG" || true
if [ "$status" -ne 0 ]; then
  echo "--- 构建失败,完整日志见 $LOG,末尾 30 行: ---"
  tail -30 "$LOG"
fi
exit "$status"
```

- [ ] **Step 4: 创建 Scripts/test.sh**

```bash
#!/usr/bin/env bash
# 在 iOS 模拟器上运行单元测试。
# 不能用 `swift test`:本包仅依赖 UIKit,在 macOS 宿主上会失败。
#
# 用法:
#   Scripts/test.sh                                   跑全部测试
#   Scripts/test.sh SwiftyUITests/SwiftyColorTests    只跑某个 test case
set -euo pipefail
cd "$(dirname "$0")/.."

# 动态解析一台可用的 iPhone 模拟器。
# 不能写 name=iPhone 16 Pro:同名设备存在 arm64 与 x86_64 两条记录,xcodebuild 会因歧义失败。
UDID="$(xcrun simctl list devices available | awk -F'[()]' '/    iPhone/ {print $2}' | tail -1)"
if [ -z "$UDID" ]; then
  echo "错误:找不到可用的 iPhone 模拟器" >&2
  exit 1
fi

ARGS=()
if [ $# -gt 0 ]; then
  ARGS+=(-only-testing:"$1")
fi
# 注意展开写法:macOS 自带 /bin/bash 是 3.2.57,在 set -u 下展开空数组
# `"${ARGS[@]}"` 会报 "unbound variable"(bash 4.4 才修正)。
# 下面调用处统一用 ${ARGS[@]+"${ARGS[@]}"} 规避。

LOG=".build/test.log"
mkdir -p .build

set +e
xcodebuild test \
  -workspace .swiftpm/xcode/package.xcworkspace \
  -scheme SwiftyUI \
  -destination "platform=iOS Simulator,id=$UDID" \
  -derivedDataPath .build/xcode \
  ${ARGS[@]+"${ARGS[@]}"} > "$LOG" 2>&1
status=$?
set -e

grep -E "^(Test Case|Test Suite 'All tests'|/.*error:|\*\* TEST)" "$LOG" || true
if [ "$status" -ne 0 ]; then
  echo "--- 测试失败,完整日志见 $LOG,末尾 40 行: ---"
  tail -40 "$LOG"
fi
exit "$status"
```

`Tests/SwiftyUITests/TestSupport.swift`:

```swift
import UIKit

/// 测试公用工具。所有测试图片都在内存中确定性生成,不依赖任何资源文件。
enum TestSupport {

    /// 生成一张纯色图片。
    static func makeSolidImage(color: UIColor,
                               size: CGSize = CGSize(width: 32, height: 32)) -> UIImage {
        let format = UIGraphicsImageRendererFormat()
        format.scale = 1
        format.opaque = false
        return UIGraphicsImageRenderer(size: size, format: format).image { ctx in
            color.setFill()
            ctx.fill(CGRect(origin: .zero, size: size))
        }
    }

    /// 生成一张左右两色的图片,用于取色算法测试。
    /// 左半宽度占 40%,右半占 60%,因此右色是出现次数更多的一方。
    static func makeTwoToneImage(left: UIColor,
                                 right: UIColor,
                                 size: CGSize = CGSize(width: 100, height: 100)) -> UIImage {
        let format = UIGraphicsImageRendererFormat()
        format.scale = 1
        format.opaque = true
        return UIGraphicsImageRenderer(size: size, format: format).image { ctx in
            left.setFill()
            ctx.fill(CGRect(x: 0, y: 0, width: size.width * 0.4, height: size.height))
            right.setFill()
            ctx.fill(CGRect(x: size.width * 0.4, y: 0, width: size.width * 0.6, height: size.height))
        }
    }
}
```

```swift
import XCTest
import UIKit
@testable import SwiftyUI

final class SmokeTests: XCTestCase {

    /// 验证 @testable import 生效、UIKit 可用、测试能在模拟器上跑起来。
    func testHarnessIsWired() {
        let color = UIColor.hex(0xCCFF00)
        XCTAssertEqual(color.redValue, 204.0 / 255.0, accuracy: 0.001)
        XCTAssertEqual(color.greenValue, 1.0, accuracy: 0.001)
        XCTAssertEqual(color.blueValue, 0.0, accuracy: 0.001)
    }

    /// 验证 TestSupport 能生成图片。
    func testSupportProducesImages() {
        let image = TestSupport.makeSolidImage(color: .red)
        XCTAssertEqual(image.size, CGSize(width: 32, height: 32))
        XCTAssertNotNil(image.cgImage)
    }
}
```

```swift
import XCTest
@testable import SwiftyUI

final class SwiftyThreadPoolTests: XCTestCase {

    /// 每个测试用独立实例,避免污染全局单例
    private var pool: SwiftyThreadPool!

    override func setUp() {
        super.setUp()
        pool = SwiftyThreadPool()
    }

    override func tearDown() {
        pool.cancel()
        pool = nil
        super.tearDown()
    }

    // MARK: - 基本操作

    func testAddedOperationExecutes() {
        let done = expectation(description: "operation 执行")
        pool.add(BlockOperation { done.fulfill() })
        wait(for: [done], timeout: 5.0)
    }

    func testOperationLookupByIdentifier() {
        let blocker = expectation(description: "operation 开始")
        let release = expectation(description: "允许 operation 结束")

        pool.add(BlockOperation {
            blocker.fulfill()
            _ = XCTWaiter.wait(for: [release], timeout: 5.0)
        }, withIdentifier: "test.op")

        wait(for: [blocker], timeout: 5.0)
        XCTAssertNotNil(pool.operation(withIdentifier: "test.op"))
        XCTAssertNil(pool.operation(withIdentifier: "test.nonexistent"))
        release.fulfill()
    }

    /// remove(withIdentifier:) 的契约是:在 queue.operations 中按 name 找到匹配项并
    /// 对其调用 cancel(),找到返回 true、找不到返回 false。
    ///
    /// 用信号量把 operation 钉在"执行中"状态,使它必定还在 queue.operations 里,
    /// 从而不依赖队列并发宽度。
    ///
    /// 不要改回"用一个 blocker operation 制造背压、再断言 target 没有执行"的写法:
    /// MAX_THREAD_COUNT = 2 * activecpu - 1,在多核机器上高达数十,单个 blocker
    /// 制造不出背压;且 BlockOperation 一旦开始执行就忽略 cancel(),
    /// "已取消的 operation 不应执行"这一断言前提本身就是错的。
    /// 同理不要断言"重复移除返回 false"——执行中的 operation 仍在 queue.operations 里。
    func testRemoveByIdentifierCancelsMatchingOperation() {
        let started = expectation(description: "target 开始执行")
        let release = DispatchSemaphore(value: 0)
        defer { release.signal() }

        let target = BlockOperation()
        target.addExecutionBlock {
            started.fulfill()
            release.wait()
        }
        pool.add(target, withIdentifier: "target")
        wait(for: [started], timeout: 5.0)

        // 仍在执行中,因此仍在 queue.operations 中,应能被找到并取消
        XCTAssertTrue(pool.remove(withIdentifier: "target"))
        XCTAssertTrue(target.isCancelled, "remove 应对匹配的 operation 调用 cancel()")

        // 未知标识符应返回 false
        XCTAssertFalse(pool.remove(withIdentifier: "no-such-operation"))
    }

    // MARK: - 待修复行为的基线

    /// B9:常驻 RunLoop 的 environment operation 应当在 init 时入队,
    /// 但当前实现在 `self.queue = queue` 之前就调用了 add,导致它从未入队。
    ///
    /// 当前(错误)行为:查不到该 operation。Task 6 会把断言翻转为 XCTAssertNotNil。
    func testEnvironmentOperationIsMissing_currentBuggyBehavior() {
        XCTAssertNil(
            pool.operation(withIdentifier: "me.haoking.environmentOperation"),
            "若此断言失败,说明 B9 已被修复,请改用 Task 6 中的正确断言"
        )
    }

    /// B10:stop() 与 restart() 的实现颠倒了。
    /// stop() 本应挂起队列(isSuspended = true),当前却设为 false。
    ///
    /// 当前(错误)行为:调用 stop() 之后,新加入的 operation 仍然会执行。
    /// Task 6 会把断言翻转。
    func testStopDoesNotActuallyStop_currentBuggyBehavior() {
        pool.stop()

        let ran = expectation(description: "stop 之后 operation 仍然执行了")
        pool.add(BlockOperation { ran.fulfill() })

        wait(for: [ran], timeout: 5.0)
        // 能走到这里就说明 stop() 没有真的停住队列 —— 这正是 B10
    }
}
```

```swift
import XCTest
@testable import SwiftyUI

private struct TestError: Error {}

final class SwiftyPromiseTests: XCTestCase {

    /// 记录执行顺序的线程安全收集器
    private final class Recorder: @unchecked Sendable {
        private let lock = NSLock()
        private var items: [String] = []

        func record(_ item: String) {
            lock.lock(); defer { lock.unlock() }
            items.append(item)
        }

        var snapshot: [String] {
            lock.lock(); defer { lock.unlock() }
            return items
        }
    }

    // MARK: - 链式顺序

    func testThenChainRunsInOrder() {
        let recorder = Recorder()
        let done = expectation(description: "链条结束")

        Promise<Void>.firstly {
            recorder.record("1")
        }.then {
            recorder.record("2")
        }.then {
            recorder.record("3")
            done.fulfill()
        }.catch()

        wait(for: [done], timeout: 10.0)
        XCTAssertEqual(recorder.snapshot, ["1", "2", "3"])
    }

    func testThenCanHopToMainThread() {
        let done = expectation(description: "主线程任务执行")
        var ranOnMain = false

        Promise<Void>.firstly(on: .background) {
            // 后台
        }.then(on: .main) {
            ranOnMain = Thread.isMainThread
            done.fulfill()
        }.catch()

        wait(for: [done], timeout: 10.0)
        XCTAssertTrue(ranOnMain)
    }

    // MARK: - 值传递

    func testValuePropagatesAcrossThreads() {
        let done = expectation(description: "值传递")
        var received: String?

        Promise<String>.firstly(on: .background) { update, _ in
            update("abc")
        }.then { update, value in
            var v = value
            v?.append("def")
            update(v)
        }.then(on: .main) { _, value in
            received = value
            done.fulfill()
        }.catch()

        wait(for: [done], timeout: 10.0)
        XCTAssertEqual(received, "abcdef")
    }

    // MARK: - 错误短路

    func testErrorShortCircuitsRemainingTasks() {
        let recorder = Recorder()
        let caught = expectation(description: "错误被捕获")

        Promise<Void>.firstly {
            recorder.record("1")
        }.then {
            recorder.record("2")
            throw TestError()
        }.then {
            recorder.record("3-不应执行")
        }.catch { _ in
            recorder.record("catch")
            caught.fulfill()
        }

        wait(for: [caught], timeout: 10.0)
        XCTAssertFalse(recorder.snapshot.contains("3-不应执行"),
                       "抛错之后的 then 不应执行")
    }

    // MARK: - 待修复行为的基线

    /// B11:always 应当在链条终结之后执行,但当前实现在 catch() 里
    /// 先启动 alwaysTasks 再 fire() 主链条,导致 always 反而排在前面。
    ///
    /// 本测试只记录顺序,不断言对错——当前顺序取决于队列调度,不稳定。
    /// Task 7 会把它改为确定性断言:always 必须是最后一项。
    func testAlwaysOrderingBaseline() {
        let recorder = Recorder()
        let done = expectation(description: "链条结束")

        Promise<Void>.firstly {
            recorder.record("task1")
        }.then {
            recorder.record("task2")
        }.always {
            recorder.record("always")
        }.catch { _ in }

        // always 与主链条并发,没有可靠的结束信号,只能定时采样
        DispatchQueue.main.asyncAfter(deadline: .now() + 2.0) { done.fulfill() }
        wait(for: [done], timeout: 10.0)

        print("BASELINE always 顺序 = \(recorder.snapshot)")
        XCTAssertTrue(recorder.snapshot.contains("always"), "always 至少应该执行过")
    }
```

- [ ] **Step 3: 重写 SwiftyPromise 的状态管理与终结语义**

`Sources/SwiftyPromise.swift` 中,把 `Task` 更名为 `PromiseTask`(与 Swift 并发的 `Task` 同名会在 Swift 6 下产生歧义),并把 `Promise` 类改为:

```swift
public final class Promise<T>
{
    /// 保护下方全部可变状态。所有临界区都很短,串行队列足够,不需要更复杂的方案。
    private let stateQueue = DispatchQueue(label: "me.haoking.SwiftyPromise.state")

    private var tasks: [PromiseTask] = []
    private var alwaysTasks: [PromiseTask] = []
    private var errorBlock: ((Error) -> Void)?
    private var isError: Bool = false
    private var isFinished: Bool = false
    private var value: T?

    // MARK: - 状态访问(全部经由 stateQueue)

    private func withState<R>(_ body: () -> R) -> R {
        return stateQueue.sync(execute: body)
    }

    private func markError(_ error: Error) {
        let handler: ((Error) -> Void)? = withState {
            self.isError = true
            return self.errorBlock
        }
        handler?(error)
    }

    private func update(_ newValue: T?) {
        withState { self.value = newValue }
    }

    private var currentValue: T? {
        return withState { self.value }
    }

    // MARK: - 任务构建

    private func operationBuild(_ work: (() throws -> Void)?) -> Operation
    {
        return BlockOperation { [weak self] in
            guard let self = self else { return }
            do {
                try work?()
            } catch {
                self.markError(error)
            }
        }.complete(with: { [weak self] in
            self?.fire()
        })
    }

    private func operationBuildT(_ work: @escaping (_ update: (T?) -> Void, _ value: T?) throws -> Void) -> Operation
    {
        return BlockOperation { [weak self] in
            guard let self = self else { return }
            do {
                try work(self.update, self.currentValue)
            } catch {
                self.markError(error)
            }
        }.complete(with: { [weak self] in
            self?.fire()
        })
    }

    // MARK: - 构造

    private init(_ identifier: String? = nil, _ perform: ThreadPerform = .background, _ work: (() throws -> Void)?)
    {
        tasks.append(.create(identifier, perform, operationBuild(work)))
    }

    private init(_ identifier: String? = nil, _ perform: ThreadPerform = .background, work: @escaping (_ update: (T?) -> Void, _ value: T?) throws -> Void)
    {
        tasks.append(.create(identifier, perform, operationBuildT(work)))
    }

    @discardableResult
    public class func firstly(with identifier: String? = nil, on perform: ThreadPerform = .background, _ work: (() throws -> Void)?) -> Promise
    {
        return Promise(identifier, perform, work)
    }

    @discardableResult
    public class func firstly(with identifier: String? = nil, on perform: ThreadPerform = .background, work: @escaping (_ update: (T?) -> Void, _ value: T?) throws -> Void) -> Promise
    {
        return Promise(identifier, perform, work: work)
    }

    // MARK: - 链式

    @discardableResult
    public func then(with identifier: String? = nil, on perform: ThreadPerform = .background, _ work: (() throws -> Void)?) -> Promise
    {
        withState { tasks.append(.create(identifier, perform, operationBuild(work))) }
        return self
    }

    @discardableResult
    public func then(with identifier: String? = nil, on perform: ThreadPerform = .background, work: @escaping (_ update: (T?) -> Void, _ value: T?) throws -> Void) -> Promise
    {
        withState { tasks.append(.create(identifier, perform, operationBuildT(work))) }
        return self
    }

    @discardableResult
    public func always(with identifier: String? = nil, on perform: ThreadPerform = .background, _ work: (() throws -> Void)?) -> Promise
    {
        // always 的 operation 不参与 fire() 链条,完成后无需推进
        let operation = BlockOperation { try? work?() }
        withState { alwaysTasks.append(.create(identifier, perform, operation)) }
        return self
    }

    // MARK: - 终结

    /// 启动链条。不提供错误处理时使用;链条必须被终结,否则永远不会执行。
    public func start()
    {
        fire()
    }

    /// 启动链条,并在出错时回调。
    public func `catch`(_ errorBlock: ((Error) -> Void)? = nil)
    {
        withState { self.errorBlock = errorBlock }
        fire()
    }

    // MARK: - 推进

    private func fire()
    {
        enum Next {
            case run(PromiseTask)
            case finish([PromiseTask])
            case nothing
        }

        let next: Next = withState {
            guard !isFinished else { return .nothing }

            if isError {
                // 出错:丢弃剩余任务,直接进入终结
                tasks.removeAll()
                isFinished = true
                let pending = alwaysTasks
                alwaysTasks.removeAll()
                return .finish(pending)
            }

            if let task = tasks.first {
                tasks.removeFirst()
                return .run(task)
            }

            // 正常跑完
            isFinished = true
            let pending = alwaysTasks
            alwaysTasks.removeAll()
            return .finish(pending)
        }

        switch next {
        case .run(let task):
            task.start()
        case .finish(let pending):
            // always 在链条终结之后才执行(B11)
            for task in pending {
                task.start()
            }
        case .nothing:
            break
        }
    }
}
```

```swift
import UIKit

/// 内存图片缓存的接口。
///
/// 1.x 曾用 associated object 在协议扩展中模拟存储属性,这既有 objc runtime
/// 开销,又在并发下必然丢更新(B4)。2.0 起协议只声明契约,存储由实现者提供。
public protocol ImageCacheable: AnyObject
{
    /// 缓存上限。超过后触发淘汰。
    var memoryCapacity: UInt64 { get set }
    /// 淘汰后期望回落到的用量。
    var preferredMemoryUsage: UInt64 { get set }
    /// 当前用量。
    var memoryUsage: UInt64 { get }

    func add(_ image: UIImage, withIdentifier identifier: String)
    @discardableResult
    func removeImage(withIdentifier identifier: String) -> Bool
    @discardableResult
    func removeAllImages() -> Bool
    func image(withIdentifier identifier: String) -> UIImage?
}

/// 缓存条目。
final class CachedImage
{
    let image: UIImage
    let identifier: String
    let totalBytes: UInt64
    var lastAccessDate: Date

    init(_ image: UIImage, identifier: String) {
        self.image = image
        self.identifier = identifier
        self.lastAccessDate = Date()
        let size = CGSize(width: image.size.width * image.scale,
                          height: image.size.height * image.scale)
        let bytesPerPixel: CGFloat = 4.0
        let bytesPerRow = size.width * bytesPerPixel
        self.totalBytes = UInt64(bytesPerRow) * UInt64(size.height)
    }

    func accessImage() -> UIImage {
        lastAccessDate = Date()
        return image
    }
}
```

- [ ] **Step 4: 把存储与实现下沉到 ImageCachePool**

`Sources/SwiftyImage.swift` 中的 `ImageCachePool` 改为:

```swift
public final class ImageCachePool: ImageCacheable, @unchecked Sendable
{
    public static let `defalut`: ImageCachePool = {
        return ImageCachePool()
    }()

    // 一把锁保护下面全部状态。缓存操作的临界区都很短,
    // 比 1.x 的并发队列 + barrier/sync 混用既更快也更正确(B4/B5)。
    private let lock = NSLock()
    private var cachedImages: [String: CachedImage] = [:]
    private var currentMemoryUsage: UInt64 = 0
    private var _memoryCapacity: UInt64 = 100_000_000
    private var _preferredMemoryUsage: UInt64 = 60_000_000

    private var memoryWarningObserver : (any NSObjectProtocol)?

    init()
    {
        memoryWarningObserver = NotificationCenter.default.addObserver(
            forName: UIApplication.didReceiveMemoryWarningNotification,
            object: nil,
            queue: nil
        ) { [weak self] _ in
            self?.removeAllImages()
        }
    }

    deinit
    {
        if let observer = memoryWarningObserver {
            NotificationCenter.default.removeObserver(observer)
        }
    }

    // MARK: - 容量

    public var memoryCapacity: UInt64 {
        get { lock.lock(); defer { lock.unlock() }; return _memoryCapacity }
        set { lock.lock(); defer { lock.unlock() }; _memoryCapacity = newValue }
    }

    public var preferredMemoryUsage: UInt64 {
        get { lock.lock(); defer { lock.unlock() }; return _preferredMemoryUsage }
        set { lock.lock(); defer { lock.unlock() }; _preferredMemoryUsage = newValue }
    }

    public var memoryUsage: UInt64 {
        lock.lock(); defer { lock.unlock() }
        return currentMemoryUsage
    }

    // MARK: - 存取

    /// 加入缓存。
    ///
    /// 1.x 用两个异步 barrier 块完成,调用方无法知道何时落地。
    /// 2.0 起同步完成,行为可预测。
    public func add(_ image: UIImage, withIdentifier identifier: String)
    {
        lock.lock()
        defer { lock.unlock() }

        let cachedImage = CachedImage(image, identifier: identifier)
        if let previous = cachedImages[identifier] {
            currentMemoryUsage = currentMemoryUsage >= previous.totalBytes
                ? currentMemoryUsage - previous.totalBytes
                : 0
        }
        cachedImages[identifier] = cachedImage
        currentMemoryUsage += cachedImage.totalBytes

        purgeIfNeededLocked()
    }

    @discardableResult
    public func removeImage(withIdentifier identifier: String) -> Bool
    {
        lock.lock()
        defer { lock.unlock() }

        guard let cachedImage = cachedImages.removeValue(forKey: identifier) else { return false }
        // 1.x 直接做 UInt64 减法,计数一旦漂移就 trap(B5)
        currentMemoryUsage = currentMemoryUsage >= cachedImage.totalBytes
            ? currentMemoryUsage - cachedImage.totalBytes
            : 0
        return true
    }

    @discardableResult
    public func removeAllImages() -> Bool
    {
        lock.lock()
        defer { lock.unlock() }

        guard !cachedImages.isEmpty else { return false }
        cachedImages.removeAll()
        currentMemoryUsage = 0
        return true
    }

    public func image(withIdentifier identifier: String) -> UIImage?
    {
        lock.lock()
        defer { lock.unlock() }

        guard let cachedImage = cachedImages[identifier] else { return nil }
        return cachedImage.accessImage()
    }

    // MARK: - 淘汰

    /// 调用方必须已持有 lock。
    private func purgeIfNeededLocked()
    {
        guard currentMemoryUsage > _memoryCapacity else { return }

        let bytesToPurge = currentMemoryUsage - _preferredMemoryUsage
        // 按最后访问时间升序:最久未访问的排在最前,优先淘汰
        let sorted = cachedImages.values.sorted { $0.lastAccessDate < $1.lastAccessDate }

        var bytesPurged: UInt64 = 0
        for cachedImage in sorted {
            cachedImages.removeValue(forKey: cachedImage.identifier)
            bytesPurged += cachedImage.totalBytes
            if bytesPurged >= bytesToPurge { break }
        }

        currentMemoryUsage = currentMemoryUsage >= bytesPurged
            ? currentMemoryUsage - bytesPurged
            : 0
    }
}
```

```swift
import UIKit

/// 用 TextKit 自绘文本的轻量标签。
///
/// 继承 UIView 而非 UILabel,绘制路径更短。全部属性为真实存储属性,
/// 读取不经过 objc runtime(1.x 用 associated object,每帧每个 label
/// 至少 4 次哈希查找)。
public class SwiftyLabel: UIView, TextEditable
{
    // MARK: - TextKit

    private let container = NSTextContainer()
    private let layoutManager = NSLayoutManager()

    // MARK: - 存储属性

    public var usesIntrinsicContentSize: Bool = true {
        didSet { setNeedsDisplay() }
    }

    public var textAlignment: TextContentAlignment = .center {
        didSet { setNeedsDisplay() }
    }

    public var font: UIFont = .systemFont(ofSize: UIFont.systemFontSize) {
        didSet { setNeedsDisplay() }
    }

    /// 2.0 起为非可选。1.x 声明为 UIColor? 但 getter 永不返回 nil,
    /// 且合成属性字符串时对它强解包。
    public var textColor: UIColor = .black {
        didSet { setNeedsDisplay() }
    }

    public var paragraphStyle: NSParagraphStyle = .default {
        didSet { setNeedsDisplay() }
    }

    public var shadow: NSShadow? = nil {
        didSet { setNeedsDisplay() }
    }

    public var attributedText: NSAttributedString? = nil {
        didSet { setNeedsDisplay() }
    }

    // MARK: - 经由 NSTextContainer 的属性

    /// 默认 0,表示不限行数。
    public var numberOfLines: Int {
        get { container.maximumNumberOfLines }
        set { container.maximumNumberOfLines = newValue; setNeedsDisplay() }
    }

    /// NSTextContainer 的 lineFragmentPadding。默认 0。
    public var padding: CGFloat {
        get { container.lineFragmentPadding }
        set { container.lineFragmentPadding = newValue; setNeedsDisplay() }
    }

    /// 默认 byTruncatingTail。
    public var lineBreakMode: NSLineBreakMode {
        get { container.lineBreakMode }
        set { container.lineBreakMode = newValue; setNeedsDisplay() }
    }

    /// 纯文本。读取时返回 attributedText 的字符串内容。
    public var text: String? {
        get { attributedText?.string }
        set {
            if let newValue = newValue {
                attributedText = NSAttributedString(string: newValue)
            } else {
                attributedText = nil
            }
        }
    }

    // MARK: - 构造

    public init(_ text: String? = nil, _ textColor: UIColor? = nil, _ backgroundColor: UIColor? = nil)
    {
        super.init(frame: .zero)

        layoutManager.addTextContainer(container)

        container.maximumNumberOfLines = 0
        container.lineFragmentPadding = 0
        container.lineBreakMode = .byTruncatingTail

        isHidden = false
        alpha = 1.0
        contentMode = .redraw
        isUserInteractionEnabled = false

        self.text = text
        if let textColor = textColor { self.textColor = textColor }
        self.backgroundColor = backgroundColor
    }

    public required init?(coder aDecoder: NSCoder) {
        fatalError("init(coder:) has not been implemented")
    }

    // MARK: - 绘制

    private var mergedAttributedText: NSAttributedString? {
        guard let attributedText = attributedText else { return nil }
        let result = NSMutableAttributedString(attributedString: attributedText)
        result.fillMissingAttribute(.font, value: font)
        result.fillMissingAttribute(.foregroundColor, value: textColor)
        result.fillMissingAttribute(.paragraphStyle, value: paragraphStyle)
        if let shadow = shadow {
            result.fillMissingAttribute(.shadow, value: shadow)
        }
        return result
    }

    open override func draw(_ rect: CGRect)
    {
        guard let attributedText = mergedAttributedText else { return }

        let storage = NSTextStorage(attributedString: attributedText)
        storage.addLayoutManager(layoutManager)

        container.size = rect.size
        let used = layoutManager.usedRect(for: container)
        let origin = textAlignment.alignOffset(viewSize: rect.size,
                                               containerSize: used.integral.size)

        let glyphRange = layoutManager.glyphRange(for: container)
        layoutManager.drawBackground(forGlyphRange: glyphRange, at: origin)
        layoutManager.drawGlyphs(forGlyphRange: glyphRange, at: origin)
    }

    open override var intrinsicContentSize: CGSize
    {
        guard usesIntrinsicContentSize else { return bounds.size }
        guard let attributedText = mergedAttributedText else { return .zero }

        let constraint = CGSize(width: bounds.width, height: .greatestFiniteMagnitude)
        return attributedText.boundingRect(
            with: constraint,
            options: [.usesLineFragmentOrigin, .usesFontLeading],
            context: nil
        ).integral.size
    }

    open override func sizeThatFits(_ size: CGSize) -> CGSize
    {
        guard let attributedText = mergedAttributedText else { return .zero }

        let storage = NSTextStorage(attributedString: attributedText)
        storage.addLayoutManager(layoutManager)

        container.size = size
        return layoutManager.usedRect(for: container).integral.size
    }

    open override func sizeToFit()
    {
        super.sizeToFit()
        frame.size = sizeThatFits(CGSize(width: bounds.width, height: .greatestFiniteMagnitude))
    }
}

private extension NSMutableAttributedString
{
    /// 只在该属性尚未设置的区间填入默认值,不覆盖调用方通过
    /// attributedText 显式指定的属性。
    func fillMissingAttribute(_ name: NSAttributedString.Key, value: Any)
    {
        let full = NSRange(location: 0, length: length)
        enumerateAttribute(name, in: full, options: .reverse) { existing, range, _ in
            if existing == nil {
                addAttributes([name: value], range: range)
            }
        }
    }
}
```

整体替换为:

```swift
import UIKit

/// 轻量视图基类:自动维护 isOpaque,减少离屏混合。
public class SwiftyView : UIView
{
    public init()
    {
        super.init(frame: .zero)
        isHidden = false
        alpha = 1.0
        backgroundColor = .clear
    }

    public required init?(coder aDecoder: NSCoder) {
        fatalError("init(coder:) has not been implemented")
    }

    // 用属性观察替代 1.x 对整个 App 所有 UIView 的 swizzle(B15)
    public override var backgroundColor: UIColor? {
        didSet { updateOpaque() }
    }

    public override var alpha: CGFloat {
        didSet { updateOpaque() }
    }
}

public extension UIView
{
    /// 添加到父视图并返回自身,便于链式调用。
    ///
    /// 1.x 在这里惰性触发全局 swizzle,导致 App 行为取决于是否调用过本方法。
    /// 2.0 起本方法无副作用(B15)。
    @discardableResult
    final func addTo(_ view: UIView) -> Self
    {
        view.addSubview(self)
        return self
    }

    /// 根据背景色与 alpha 重算 isOpaque。
    ///
    /// 完全不透明的视图可以让合成器跳过混合。
    final func updateOpaque()
    {
        if let color = backgroundColor, color.alphaValue == 1.0, alpha == 1.0 {
            isOpaque = true
        } else {
            isOpaque = false
        }
    }
}

/// 库级配置入口。
@MainActor
public enum SwiftyUI
{
    private static var didEnableGlobalOpaqueOptimization = false

    /// 为宿主 App 中**所有** UIView 自动维护 isOpaque。
    ///
    /// 实现方式是 swizzle UIView 的 backgroundColor 与 alpha setter,
    /// 因此会影响整个 App,包括你没有使用 SwiftyUI 的部分。
    /// 默认不启用;需要这项收益的调用方显式开启并自行承担风险。
    ///
    /// 重复调用无效果。必须在主线程调用。
```

- [ ] **Step 3: 实现 async 桥接**

在 `Promise` 类中追加:

```swift
    /// 终结链条并以 await 取回最终值。
    ///
    /// 链条中的错误经由 throws 抛出。与 start() / catch(_:) 一样,
    /// 本方法也是终结符——同一个 Promise 只能终结一次。
    public func value() async throws -> T?
    {
        return try await withCheckedThrowingContinuation { continuation in
            // 用一个 box 保证 continuation 只被恢复一次:
            // 链条正常结束与出错是互斥的,但两条路径都会走到这里。
            let resumed = ResumeGuard()

            self.always(on: .background) { [weak self] in
                guard resumed.claim() else { return }
                continuation.resume(returning: self?.currentValue)
            }.catch { error in
                guard resumed.claim() else { return }
                continuation.resume(throwing: error)
            }
        }
    }
```

并在文件末尾添加:

```swift
/// 保证 CheckedContinuation 只被恢复一次。
private final class ResumeGuard: @unchecked Sendable
{
    private let lock = NSLock()
    private var claimed = false

    /// 首次调用返回 true,之后一律返回 false。
    func claim() -> Bool
    {
        lock.lock()
        defer { lock.unlock() }
        guard !claimed else { return false }
        claimed = true
        return true
    }
}
```

> **注意执行顺序**:Task 7 已保证 `always` 在链条终结之后执行,而 `catch` 的 errorBlock 在出错时立即调用。出错时两者都会触发,`ResumeGuard` 确保先到者胜出——由于 `markError` 先于 `fire()` 的终结分支,错误路径会先 claim 成功,行为正确。

- [ ] **Step 1: 创建工作流**

`.github/workflows/ci.yml`:

```yaml
name: CI

on:
  push:
    branches: [master, "feature/**"]
  pull_request:
    branches: [master]

jobs:
  build-and-test:
    name: 构建与测试
    runs-on: macos-15
    steps:
      - uses: actions/checkout@v4

      - name: 选择 Xcode
        run: sudo xcode-select -s /Applications/Xcode_16.app

      - name: 校验 SPM 清单
        # 不能用 swift build:本包仅依赖 UIKit,在 macOS 宿主上无法编译
        run: swift package describe

      - name: 构建库
        run: Scripts/build.sh

      - name: 运行单元测试
        run: Scripts/test.sh

      - name: 构建示例工程
        run: |
          set +e
          xcodebuild build -scheme iOSExample \
            -destination 'generic/platform=iOS Simulator' \
            -derivedDataPath .build/xcode-example > .build/example.log 2>&1
          status=$?
          set -e
          grep -E '^(/.*(error|warning):|\*\* BUILD)' .build/example.log || true
          [ "$status" -eq 0 ] || tail -30 .build/example.log
          exit "$status"

  lint-podspec:
    name: podspec 校验
    runs-on: macos-15
    steps:
      - uses: actions/checkout@v4
      - name: 选择 Xcode
        run: sudo xcode-select -s /Applications/Xcode_16.app
      - name: pod lib lint
        run: pod lib lint --allow-warnings
```

```markdown
- **B5** 内存计数 `UInt64` 下溢 trap
- **B6** `sort(by:)` 谓词使用 `<=` 违反严格弱序(未定义行为)
- **B7** `SwiftyPromise` 内部状态跨线程无同步
- **B8** `SwiftyToastCenter` 队列状态跨线程无同步
- **B9** 线程池的常驻 RunLoop operation 从未入队

- **B11** `always` 在链条之前执行,而非之后
- **B12** 取色算法中整数除法使阈值失效
- **B13** `isDistinct` 内层判断被无条件覆盖,是死代码
- **B14** `UIImage.load` 中的局部 `NSLock` 不提供互斥,纯属开销
- **B15** 对宿主 App 全部 `UIView` 的隐式全局 swizzle

- **B19** `UIColor.hex("zzz")` 因强解包 nil 崩溃

### 新增

- `SwiftyGlobal.safeAreaInsets`
- `SwiftyThreadPool.isSuspended`
- `SwiftyPromise.start()` —— 不带错误处理的终结符
- `SwiftyPromise.value() async throws -> T?` —— async 桥接
- `SwiftyButton.ignoreEventInterval` —— 可配置的防重复点击间隔
```
